## Architecture

- *D2 (engine).* `Detail.Open` is a formula compiled on detail rows (the detail statement, beside `__label`) as `__open`. It compiles in a `rowsCtx` with `idText` set, so a relation value inside a text operator reads as its record id, not its label (R2). `assemble` reads `__open` through `openPath(slug, value)` (detail.go): a value that does not start with `<slug>/`, holds `//`, or holds any character but letters, digits, `-`, `_` and `/` gives no `open`, and the run logs once. Only detail rows get `Row.Open`; nest child rows never read `__open`.
- *D1 (engine).* `Column.Drill` binds in a new `drill.go`: the target's params come from the shipped registry (`shippedParamDefs(key)`), every refusal is a 400 at `columns.<i>.drill…`. Each value form is a part: a formula → one cell, `{ range }` → two cells (from, to), `{ group }` → one cell, `{ param }` → no cell (the compiler's raw given value of that param). Formula parts compile on the drilled level in a `levelCtx` whose new `drill` field enables the two leaves (`groupKey` → `a.k<i>`, `pivotBound` → a bound day), as `dv<col idx>_<level>_<k>` cells; pivot cell parts compile per drilled level and pivot value as `dvp<col idx>_<level>_<j>_<k>`. Every level and every layout leg emits the same cell names (NULL where none), as opening cells do. `assemble` writes `<col>@drill` (Go `DrillParams`, param id → JSON in the run request's form) on a drilled level's group row and its subtotal, and on pivot cell columns; a blank formula value drops that cell's target. `run` resolves each drilled column's target once per run (`drillTargets`: `reports` row by `shipped_key`, then `FindViewableRecord`); without access the column has no `drill` and no row has its `@drill` cells.
- *D3 (client).* `from=<report id>` in the report URL. `useReportBack(fromId)` reads the source with `useReportRecord`: with its title the back link (`ReportBackLink` `label`) reads the title and returns (history back, else replace to `reports/<from>`); loading, failed or not viewable, it reads "Reports" and goes to the hub as today. `reportLink` never writes `from` or `d` keys.
- *D4 (client).* (a) `@tinycld/core/lib/detail-surface` + `use-detail-surface` (moved unchanged from Books). (b) `reports/lib/drill.ts`: `drillHref`, `drillPanelParams`, `isDrillShown`, `useOpenDrill`. (c) `parseViewOptions` / `serializeViewOptions` take a key prefix; `useReportView({ urlPrefix, uiScope })`; `report-ui-store` keeps `surface` and `isCustomizeOpen` per scope (`'main'` / `'drill'`); `ReportNotices` and `isCompact` read the view's own width. (d) `ReportDrillPanel` + `useDrillPanel` in `ReportView`'s `side` slot, panel or page by style values only. (e) `ReportScreen` hosts it; opening Customize clears `d` keys; a figure press closes Customize.
- *Builder.* `draft.ts` keeps `columns[].drill` and `detail.open` verbatim (read-only); `ColumnsSection` shows "Figures open <report title>", `DetailsSection` "Rows open their record"; the preview's figures are plain (no `drill` handler passed).

**Tech stack:** Go 1.26 (PocketBase, SQLite), TypeScript (React Native + web, expo-router), zod v4, Zustand, vitest, Playwright.

## Books plan changes (for the driver; amend before checkpoint 1)

- **B1 — the `@drill` cell's form.** A cell is an object keyed by target param id; each value is the run request's JSON for that param: a dateRange `{ "from": "YYYY-MM-DD", "to": "YYYY-MM-DD" }` or, copied by `{ param }`, the source's own posted form (`{ "preset": "thisFiscalYearToDate" }`); a multiple choice `["<id>"]` or a group pick `[{ "group": "<group value>" }]`; a single choice or a day a string. ## Review focus

1. A drill value that reads a blank (an account with no first line, a formula giving null): the cell has no `@drill`, so the figure is plain, never a link that opens an unfiltered report (Task 4 `TestADrillValueThatIsBlankLeavesTheCellWithNoTarget`).
2. An open path a package builds from data (a doc type the route table lacks gives `books//x`; a name with `?`): the row has no link and the run logs once, never a broken push (Task 1 `TestDetailOpenDropsABadPathAndLogsOncePerRun`).
3. Two report views on one route: a chip of the same id in the panel and in the statement never open each other's popover, and the main view never reads `d.` keys (Task 7 prefix tests, Task 8 `report-ui-store.test.ts`).
4. A reader who loses access to the target between runs: the next run's result has no `drill` and no `@drill` cells, so no figure links (Task 3 and Task 4 access tests).
5. A copied link while the panel is open or after a drill: it holds no `d`, `d.` or `from` key (Task 7 `reportLink` test; e2e Task 10 test 4).

## Rulings

- **R1 — a drill value's form is chosen by its keys.** A JSON object whose one key is `range` is a range, one key `group` a group pick, one key `param` (a string) a copy; anything else is a formula node, decoded strictly. A bare param leaf `{ "param": "x" }` is therefore always the copy; a formula over a param uses `bound` or an operator. Cost if wrong: none for any spec in §5; an author writes `coalesce({param})` for the leaf.
- **R2 — inside `detail.open`, a relation in a text operator reads as its record id.** The engine's text operators read a relation as its record's label (`asText` → `label`). A path holds ids, so `open` compiles in a `rowsCtx` whose `idText` makes `label(e)` return the id. Cost if wrong: none; no open path wants a label.
- **R3 — which value forms fit a target param.** dateRange: `range`, or `param` of a dateRange. date / asOf: a formula of type date or datetime (written as its first 10 characters, a day), or `param` of the same type. choice, single: a formula of type text, select or relation (written as text: a relation as its id, a select as its stored value), or `param` of a single choice. choice, multiple: a formula of those types (written `[value]`), `group` (only when the target's `optionsFrom.group` is set; written `[{ "group": value }]`), or `param` of a multiple choice. text, number, amount: `param` of the same type only. Anything else is refused (400, "a … value does not fit param <id>"). A formula's type is known when it compiles, so its fit is refused by `Validate`'s dry compile (`columns.<i>.drill.levels.<g>.<param>`).
- **R4 — `{ param }` copies the posted value.** It writes the run's given JSON of that source param (else its default) unchanged, so a preset stays a preset, All dates stays All dates and an amount posted as bare cents is written as `{ "amount": <cents>, "currency": "" }`, because the URL reads a bare number as units (every other posted form is written as posted); an unset source param writes JSON `null` (the target clears it). It is never a "blank value": it does not drop the target.
- **R5 — a blank formula value drops the cell's target.** A formula, a range bound or a group value that is NULL (or a range whose `from` is after its `to`, or a day that is not a day) leaves that cell with no `@drill` at all.
- **R6 — `pivotCells` goes on the pivot's cell column**, and only there (400 otherwise). Pivot cell parts that read `pivotBound` compile once per pivot value. A pivot value whose key is no bucket (a dry compile's placeholder values, a blank date's column) compiles over the placeholder days `0001-01-01`..`0001-01-01`, so `Validate` still refuses a misfit, and its cell is `NULL` (no target, R5).
- **R7 — `groupKey` and `pivotBound` are leaves of drill values only.** A context that does not implement `drillLeaves` (filter, detail rows, lookups, layout, sort, label) refuses them: "groupKey is read only in a drill value" / "pivotBound is read only in a drill's pivotCells". So neither is read inside a lookup.
- **R8 — the target is resolved once per run, for the reader.** `drillTargets` finds the `reports` row by `shipped_key` and checks it with `FindViewableRecord`; `sql.ErrNoRows` (no row yet, or not viewable) means no access; any other error fails the run. A dry compile (`Validate`) resolves none.
- **R9 — the client encodes a drill value by its JSON form** (`encodeDrillValue`): `{ preset }` → the preset, `{ from, to }` → `from..to`, a list → its JSON, a string → itself, a number → its text, `{ amount, currency }` → "<cents as text> <code>", `null` → no key (the target's default: the URL has no form for "cleared", so an unset source param opens on the target's default; cost: a target whose default filters shows fewer rows than the figure until the reader clears that chip). This is the text `encodeParamValue` writes for the same value, pinned by a round trip through `decodeParamValue` over the target's params; the figure has no target defs, so `drillHref` cannot go through `serializeViewOptions`. Open as full report does go through `serializeViewOptions` (the panel has the defs). Cost if wrong: one encoder drifts from the other; the round-trip test catches it.
- **R10 — `from` and `d` keys stay out of a copied link** because `reportLink` writes only `serializeViewOptions(defs, options)` with no prefix; the test pins it.
- **R11 — the store keeps one shape per scope**, `scopes.main` and `scopes.drill`; every action takes the scope, default `'main'`, so the hub's `startVisit` and every existing caller keep their meaning. `startVisit` resets both scopes.
- **R12 — `ResultRow.cells` stays `Record<string, CellValue>`.** A `@drill` cell is an object; `drillCellParams` reads it as `unknown` and checks its shape. Widening `CellValue` would make every cell reader handle an object. Cost if wrong: one cast in tests that build `@drill` cells.
- **R13 — the panel mounts in Task 14**, in `SavedReportView`'s `side`, with `hasPanel: true`; Task 15 adds only focus return and Customize's close. A panel that is drawn by no screen cannot be tested.
- **R14 — test 5 proves "no remount" by a DOM mark and "no rerun" by request bodies.** The test sets `data-e2e-kept` on the panel's `report-table`; React does not touch an attribute it does not render, so the mark lasts as long as the element. Every target run request after a crossing has the same body as the last one before it; a count is not used, because live reruns caused by other tests' writes to the shared DB send the same body.
- **R15 — the reader without access is a fresh invited member** (`createInvitedUser`): guests do not see published reports. The target is unpublished (only the shipped owner may view it); the drilled reports are published.
- **R16 — an unviewable `from` is tested with a well-formed id of no report** (`zzzzzzzzzzzzzzz`): the client reads an unviewable record and a missing one the same way (`state: 'missing'`).
- **Deviation from brief Do step 2:** `drillHref` does not build its URL through `serializeViewOptions` (the figure has no target defs); see R9 and its round-trip test. Open as full report does.
