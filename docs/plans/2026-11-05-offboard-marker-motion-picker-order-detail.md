### Task 1 (D3): exported offboarded predicate

**Brief:** core offboard anonymizes a leaver (sentinel email via unexported `deletedEmailDomain`, name "Deleted user", random password; role, `disabled`, org_pkg_access stay). PocketBase runs `OnRecordAfterUpdateSuccess('users')` at commit, so a package hook that grants rows on a users update re-grants rows core removed. Add an exported, documented predicate packages call, with Go tests (a fictional package hook that must skip an offboarded user). Document it in docs/packages.md next to RegisterHandler/RegisterReassignable.

**Design (ruling):** `offboard.IsOffboarded(user *core.Record) bool` in `core/server/offboard/offboard.go`. It is true when the record's email is exactly the sentinel `deleted-<user.Id>@deleted.tinycld.org` (a helper `sentinelEmail(id string) string` used by `anonymizeUser` and the predicate; `nil` → false). No stored field. Why: the sentinel is already written in the same `app.Save` that fires the users update hooks, so it is visible at commit with no migration on the core `users` collection; it persists on every later save; a non-admin cannot set it (an email change needs confirmation at that address, users_guard.go), and binding it to the record id stops a copied value from marking another user. A stored bool would need a users migration, a field guard so a user cannot set it on themselves, and a second write path that can drift from the email.

**Files:** Modify `core/server/offboard/offboard.go` (sentinel helper + `IsOffboarded`, doc comment saying a package hook that grants rows from a users update must skip an offboarded user). Test: `core/server/offboard/offboarded_test.go` (new). Modify `docs/packages.md` (offboard registries section, ~line 912-950).

### Task 3 (E1): source-backed choice options grouped in a defined order

**Brief:** a picker's groups list A–Z today; a chart of accounts wants chart order (Assets, Liabilities, Equity, Income, Expense — the order the group field's values are declared in, or a sort key). Add an optional spec field on `params[].optionsFrom`, Go validation, TS types, builder editing, help ("Filters that list records") and packages.md, and tests.

**Facts read by the planner:** `OptionsFrom` (`core/server/reports/spec.go:221`); bound in `binder.optionSources` (`bind.go:220`); alias walk `alias.go:55-65`; groups SQL `optionGroups` orders `o.g <> '', orderKey(typ, gl), 1` (`options.go` ~line 345); options page orders `o.l <> '', orderKey(label), o.v` with cursor `[label, value]` (`options.go` ~line 300, `optionsCursor`); a Select `Field.Options` keeps declared order (`registry.go:85`); client `optionSections` keeps the server's group order (`core/reports/lib/param-options.ts:45`); builder fields "Group the list by" / "Whole group text" live in `core/reports/components/builder/ConditionValues.tsx`, draft mapping in `core/reports/lib/builder/draft.ts` / `filter.ts`; `params.go:93` checks groupLabel.

**Design (ruling):** `optionsFrom.groupOrder` (optional, needs `group`):
- `{"by": "label"}` or omitted — today's order (blank group first, then by group label; a number by value).
- `{"by": "declared"}` — the group field's declared option order; refused unless the group path ends at a Select field (`params.N.optionsFrom.groupOrder`: "declared order needs a select group field"). Group values no option names come after the named ones, by label; the blank group stays first.
- `{"by": "path", "path": Path}` — by the smallest value of `path` (a to-one path read from the options source, bound like `group`) over each group's options, then by label; blank group first. Refused if the path does not bind.
Any other `by`, or `groupOrder` without `group`, is refused. Go: `type GroupOrder struct { By string "json:\"by\""; Path Path "json:\"path,omitempty\"" }`, consts `GroupOrderLabel/Declared/Path`. TS: `groupOrder?: { by: 'label' } | { by: 'declared' } | { by: 'path'; path: Path }` in `core/reports/lib/spec.ts`. Alias walk resolves `groupOrder.path`. ALSO (ruling, same defect class): when options have a group, the options PAGE orders by the group's position first (the same order the groups list uses), then label, then value, and the cursor carries the group position, so each page only appends to the end of what the reader sees.

### Task 4 (E2): a column can be blank on detail rows

**Brief:** when an account group is opened, each detail row repeats the group's key column value ("1000" in No. on every line). Add a general way so a column that only identifies the group is blank on its detail rows, Go + TS tests, builder support, help and packages.md; must work in the wrapped phone layout (E14).

**Facts read by the planner:** detail rows are built in `runner.detail` (`assemble.go` ~line 335): label from `firstLabel` (first column) or `detail.label`; cells from `rn.cells(row)`. The client drops `labelColumn` from a detail row's cells (`core/reports/lib/rows.ts:22-32`). Per-column builder fields live in `core/reports/components/builder/ColumnsSection.tsx` (`TotalField` at ~line 134 is the pattern).

**Design (ruling):** explicit `columns[].detail: "blank"` (optional; omitted = shown). The engine omits that column's cell (and its `@currency` cell) from rows of kind `detail`; group, subtotal and total rows are unchanged. Validation: refused (`columns.N.detail`) when the value is not `"blank"`, when the report has no groups, or when the column is the one that labels detail rows (the first column with no `detail.label`, or the column a `detail.label` of exactly `{col}` names) — a blank label would leave a row with no name. Rejected alternative: blanking a cell when it equals the open group's key — the motivating column (an account's number) is not the group key (the account record), so equality would miss it, and a figure that happens to equal a key would vanish. TS: `detail?: 'blank'` on `Column` in `core/reports/lib/spec.ts`; a missing cell renders empty (no "(none)") in the table and the wrapped phone layout.

**Files:** `core/server/reports/spec.go` (`Column.Detail`), `bind.go`/validation, `assemble.go` (`detail` / `cells`); `core/reports/lib/spec.ts`, any client cell/wrap helper that would print a missing cell as "(none)"; builder `ColumnsSection.tsx` (+ draft mapping); `core/help/reports.md`; `docs/packages.md`; e2e in `tests/e2e/reports-wrap.spec.ts` (phone) and a desktop spec (`reports-groups-v2.spec.ts` or `reports-view.spec.ts`).
