## Architecture

- *T3 (engine check).* `check.go` `compatible[Select]` gains `core.FieldTypeText`. `checkField`'s option check stays only for a `*core.SelectField` column (a text column has no values to check). A view collection already passes `partCollection` and `checkRule` (`ruleSelect` reads `{{view}}.*` under the view's list rule); Task 1's tests prove it, and any refusal they show is fixed in `check.go` / `rules.go` in Task 1. PocketBase types a view's bare `a.created` as the source field (autodate, which `DateTime` reads), a `CAST(… AS TEXT)` column as text, and an uncast expression as `json` (`third_party/pocketbase/core/view.go:381-436`). The test view `zoo_feed_log` reads `zoo_feedings`, which gains an autodate `created` and one feeding with note "secret"; its list rule `@request.auth.role = "member" && note != "secret"` refuses the guest `gus` every row.
- *T1 (client).* A new `core/reports/lib/date-time.ts` holds the `Intl` work: `readerTimeZone()`, `isTwelveHour(resolved)` (the device's clock: `hourCycle`, else `hour12`, else 12-hour), `formatDateTime(value, timeZone, hour12)`, `dateTimeText(value, timeZone?)`, `timeZoneWords(timeZone?)`. `format.ts` re-exports `dateTimeText` and `timeZoneWords` (the brief's import path) and its `cellDisplay` shows a `datetime` value through `dateTimeText` (a `date` value stays `dayText`). Row labels (`rowLabelText` → `typedLabelText`), pivot headings, the drill panel's table and a choice chip or picker option typed `datetime` (`optionText` → `typedLabelText`) all reach `cellDisplay`, so each shows the same text. `column-measure.ts` keeps room for the widest date and time (`WORST_DATE_TIME`, "Sep 30, 2026, 12:59 PM") in a `datetime` column and a `datetime` row label, because a date-time is a figure and is never cut. `format.ts` gains `zoneLine(columns, timeZone?)`; `useReportView` puts `zoneWords: zoneLine(shown columns)` on the model; `ReportDocumentHeader` draws it under the period (`report-document-zone`), in the main view and in the drill panel.
- *T2 (engine).* `Options.TimeZone` (run) and `OptionsRequest.TimeZone` / `paramOptionsBody.TimeZone` (param options) reach `readerCompiler`, which reads the zone with `readerZone(name)` (nil for no name, a name of UTC itself, `Local` or an unknown name, R2) and puts it on `periodContext.loc`. `resolveParams` gives each set param `withZonedDays`: a date-range value its zoned first and last day (`paramValue.fromZ`, `toZ`) and a date / asOf value its zoned day (`dayZ`), each a `zonedDay{start, end}`: the UTC instants (`instantLayout`, `2006-01-02 15:04:05.000Z`) of the local midnight that starts the day and the one that ends it (`localMidnight`, which steps forward where a clock change skips midnight). `paramExpr` puts a date / asOf day on `expr.zoned` and a range's days on `expr.zonedFrom` / `expr.zonedTo`; `rangeBound` gives a bound its own day on `expr.zoned`. `between` (`zonedSpan`) and `lt`/`lte`/`gt`/`gte` (`zonedCompare`) compare a `DateTime` value with a zoned operand as instants (R1); with no zone the SQL is today's. Buckets and date parts read `substr(x, 1, 10)` as today (Q7). The client adds `timeZone: readerTimeZone()` to every run body (`runReport`, as `options.timeZone`) and param-options body (`fetchParamOptions`, as a top-level `timeZone`) when it sends them.
- *D5 (generator).* A manifest's `reportPanels: { path, component }[]` is read by `scripts/gen-report-panels.ts` (`buildReportPanelsSource`), which `generate.ts` calls to write `lib/generated/report-panels.ts`: `export const reportPanels: ReportPanelEntry[] = [{ slug, path, load: () => import('<package>/<component>') }]`, the component resolved through the package's `exports` map as settings panels are (`gen-config.ts:157`). Core reads it in one module, `core/reports/lib/registered-panels.ts` (R8), which wraps each entry in `reloadableChunk` (a lazy component whose failed chunk the panel's error boundary drops, R14).
- *D5 (view).* `core/reports/lib/record-panel.ts` holds the pure rules: which registered panel an `open` path names (`recordPanelOf`), whether a row press opens it beside the report (`rowOpensInPanel`), the route params that open it (`recordPanelParams`) and whether a row is the opened one (`isRowShown`). `view-url.ts` adds `RECORD_KEY = 'dr'`; `clearedDrillKeys` clears it with the drill keys, so the side slot holds one surface. `useRowLinks.onRow` opens the panel (setParams, `openRecord(row.id)` in the UI store, Customize closes) or pushes the record's screen through `useOpenRecordScreen` (which watches the package tab so Back returns to the report). `ReportDrillPanel` reads `d` and `dr`: with `dr` it draws the record mode (`useRecordPanel` in `useDrillPanel.ts`): header (`report-record-panel-header`: the title, which the package names with `usePanelTitle` and the store files under its record path, `recordTitleOf`; Open as full screen through `useOpenRecordScreen`; ✕), Escape, the package's component in Suspense and an error boundary, panel beside the report at 1360 px or more and a page over it below (style values only, R9; the page's back link is `ReportBackLink` with test id `report-record-panel-back`). The opened row is marked (`bg-accent` on `RowFrame`, `aria-selected` on its `OpenRowLabel`, only while it is the opened row; React Native maps it to `accessibilityState.selected`), and a close sends the focus back to that label (`rowFocusKey` in `figure-focus.ts`, `RowLinks.rowKey`).

## Review focus

1. A reader whose zone the server does not know, that is `"Local"`, or that is a name of UTC itself (`Etc/UTC`, `GMT`): the run is UTC (never the server's own zone) with today's statements, and the client then also draws UTC text and "Times in UTC", so the rows and the cells agree (Task 4 `TestZoneUnknownOrLocalIsUTC`; Task 2 `dateTimeText` with an unknown zone gives the UTC text).
2. A day of 23 or 25 hours (DST start or end): the range keeps exactly the instants of the local day (Task 4 `TestBetweenAcrossDSTEnd`, Nov 1 2026, and `TestBetweenAcrossDSTStart`, Mar 8 2026); a zone whose clock change skips local midnight starts the day when the clock jumps (Task 4 `TestZoneDayWhereMidnightIsSkipped`).
3. Many rows that open one record (every audit row of one record): only the pressed row is marked, a second press on another of them moves the mark, and the panel keeps its title (Task 7 `isRowShown` test; Task 8 store test; Task 11 e2e).
4. A package panel whose chunk fails to load or whose component throws: the panel shows "Could not load this record" (`report-record-panel-error`), keeps ✕, Escape and Open as full screen, logs once (`log.error('reports.record-panel', …)`), the report beside it stays usable, and the next record opened in the panel loads the chunk again (Task 8 boundary and `reloadableChunk` test; the stub cannot fail, so the boundary is reviewed, not e2e-tested).
5. A `dr` that names no registered panel (a stale or edited link, a package removed): no panel and no error; the report shows alone (Task 7 `recordPanelOf` returns null; Task 8 `ReportDrillPanel` draws nothing).
6. A device whose `Intl` leaves out `hourCycle` but gives `hour12: false` (a Hermes build): 24-hour cells (Task 2 `isTwelveHour`; the reviewer confirms on RN 0.88 Hermes, R4).

## Rulings

- **R1 — when a comparison is zoned.** A comparison is zoned when one side's type is `DateTime` and the other side is a zoned day: a `dateRange` param (in `between`), a `date` or `asOf` param, or `bound` of a range (`expr.zoned != nil`). Then `between(x, range)` is `x >= start AND x < end`; `gte(x, d)` is `x >= d.start`, `gt(x, d)` is `x >= d.end`, `lt(x, d)` is `x < d.start`, `lte(x, d)` is `x < d.end` (the day on the left mirrors); `between(x, lo, hi)` with zoned days is `x >= lo.start AND x < hi.end`. With a range, `between(x, range)` reads `expr.zonedFrom.start` and `expr.zonedTo.end`, and `bound` from / to gives `expr.zoned` the range's first / last whole day, so `gt(x, bound from)` is `x >= from.end`. A `Date` value, a text literal day, a date column and any other operand compare as today. `expr.zoned`, `zonedFrom` and `zonedTo` are set only when the zone is not UTC, so a UTC reader's SQL is today's. Limit (stated in `docs/packages.md` and in the help, Task 9): a condition that compares a `DateTime` with a literal day (a value typed in a builder filter, such as `gte(posted_at, {value: "2026-11-14"})`) or with a date column still compares in UTC, while a period chip over the same field compares in the reader's zone. No shipped spec in the workspace does this, but a user can build such a filter (`filter.ts` offers lt/lte/gt/gte/between with day values for a `datetime` field). See Q3.
- **R2 — reading the zone in Go.** `readerZone(name)`: `""`, a name of UTC itself (`utcNames`: `"UTC"`, `"Etc/UTC"`, `"Etc/GMT"`, `"GMT"`, the same set as the client's `UTC_ZONES`), `"Local"` and any name `time.LoadLocation` refuses give nil (UTC), so every UTC reader's statements are today's and the server and the client agree on who is in UTC; `"Local"` is refused because it is the server's zone. A day of the zone is `zoneDay`: the instants of `localMidnight` of the day and of the next day; where a clock change skips midnight (America/Santiago, 2026-09-06) `localMidnight` steps forward to the first instant of the day. The reports package imports `_ "time/tzdata"` (no other core package does; about 450 KB), so a server image with no `/usr/share/zoneinfo` still knows every zone. `todayOf` with an empty `Options.Today` and a zone gives the zone's day. Cost if wrong: without tzdata every zone silently becomes UTC on a slim image.
- **R3 — the client's zone.** `readerTimeZone()` is `new Intl.DateTimeFormat().resolvedOptions().timeZone`, `'UTC'` when empty, read once per app start (cached in date-time.ts), so a cell, the header line and the run request always use one zone; Hermes (iOS and Android) supports `resolvedOptions().timeZone`. It is added to the body when it is sent (`runReport`, `fetchParamOptions`), not to the react-query key. Cost: a reader whose device changes zone while the app runs sees the old zone until the app restarts.
- **R4 — `dateTimeText` on Hermes.** `formatDateTime` asks `Intl.DateTimeFormat('en-US', { timeZone, year: 'numeric', month: 'numeric', day: 'numeric', hour: 'numeric', minute: '2-digit', hourCycle: 'h23' }).formatToParts` for the wall-clock numbers and builds the text with core's own short month names (`dates.ts`), as the day words already are (Hermes ships little locale data). A formatter is cached per zone. The hour cycle is the device locale's, read once with the zone by `isTwelveHour(new Intl.DateTimeFormat(undefined, { hour: 'numeric' }).resolvedOptions())`: `hourCycle` `h11`/`h12` → 12-hour, `h23`/`h24` → 24-hour; with no `hourCycle` (some Hermes builds), `hour12` (`false` → 24-hour); with neither → 12-hour. The reviewer confirms on RN 0.88 Hermes which of the two `resolvedOptions()` gives. A zone `Intl` refuses (a `RangeError`) gives the UTC text. Cost if wrong: on a runtime without `formatToParts` the cells show UTC; the reviewer checks Hermes support in RN 0.88's Intl.
- **R5 — how the header decides.** `zoneLine` reads the view's shown columns (`model.columns`, after Customize's hidden list): a column whose `type` is `datetime`, or a relation column whose `labelType` is `datetime`. Rows' `labelType` is not read (rows page in lazily; the line must not appear late). Cost: a report whose only date-time is the row label of a non-date-time first column shows no zone line; the audit log's first column is the date-time.
- **R6 — zone words.** `timeZoneWords` tries `Intl` `timeZoneName: 'longGeneric'` ("Central Time"); when that is missing or gives a `GMT…` offset it tries `'long'` with " Standard " / " Daylight " made " " ("Central Time"); else the IANA name's last part with `_` as a space and " time" ("Chicago time"); `UTC` and `Etc/UTC` give "UTC".
- **R7 — `dr` and the drill keys exclude each other.** `clearedDrillKeys` clears `d`, `d.*` and `dr`. `drillPanelParams` spreads it, so a figure press clears `dr`; `recordPanelParams` spreads it, so a row press clears `d` and `d.*`; Customize's open clears it (as it clears `d` today). `reportLink` writes `serializeViewOptions` with no prefix, so neither key reaches a copied link (test pins it). Cost: none.
- **R8 — where the generated list is read.** Only `core/reports/lib/registered-panels.ts` imports `@tinycld/app-generated/report-panels`; it wraps each entry's `load` in `lazyChunk` once at module scope. `record-panel.ts` (pure) takes the panels as an argument, so vitest needs no generated file; core's unit-setup mocks the module to `[]` and `types/app-generated.d.ts` declares it for core's standalone typecheck.
- **R9 — phones and narrow windows.** A press on a panel row pushes the path when the surface is `page` (below 1360 px, every phone), as today. A `dr` already in the route on a `page` surface (a reload, a resize from 1440, a pasted link) shows the record panel as a page over the report, by style values only (as the drill panel, `PAGE_STYLE`), with a back link named the report's title (`report-record-panel-back`) and no ✕; so crossing 1360 px never remounts the component. `useIsDrillPage` covers it so the report under it is covered.
- **R10 — which `dr` opens a panel.** `recordPanelOf` strips one leading `/`, needs `<slug>/<path>/` followed by at least one non-empty segment, and splits the rest on `/` (no query or hash: a `?` or `#` gives no match). A `dr` that matches no registered panel draws nothing and logs nothing; the report shows alone.
- **R11 — the marked row.** The press stores the row id (`openRecord(row.id)`); a row is marked while `row.id === openedRow` and `row.open === dr`, so of many rows that open one record only the pressed one is marked. The mark is `bg-accent` on `RowFrame` (in place of `bg-background`) and `aria-selected={isShown || undefined}` on the row's `OpenRowLabel`, the row's one accessible control (`RowFrame` is `accessible={false}`): only the opened row carries the state (ARIA has no selected state for a link, so the other rows leave it out rather than say "false"), and React Native maps it to `accessibilityState.selected` on native. `useRowLinks`' memo depends on `dr` and `openedRow`, so FlashList redraws the rows when the mark moves.
- **R12 — panel focus.** On a press the focus moves to the panel title (`recordOpens` / `recordFocused`, as `drillOpens` / `drillFocused`); on ✕, Escape or the page's back link it returns to the opened row's label through `figure-focus` (`rowFocusKey(scope, row.id)`), when that label is still drawn.
- **R13 — the title.** `usePanelTitle(title)` writes `setRecordTitle(open, title)` in a `useEffect` (a child telling its host, not derived state) only inside `PanelTitleProvider`, which gives it the panel's record path `open`; outside it (the package's full screen) it does nothing. The store keeps `recordTitle: { open, title } | null`, and the header shows `recordTitleOf(recordTitle, dr)`: empty until the component of that record sets it. So a replaced record never shows the previous title, and a press on a second row that opens the same record (the component does not remount, so its effect does not run again) keeps the title. `openRecord` does not touch the title.
- **R14 — the panel's frame.** Inside the panel the component renders in `Suspense` (fallback `report-record-panel-loading`, core `LoadingState`) inside a small error boundary in `ReportDrillPanel.tsx` (`report-record-panel-error`, "Could not load this record", `log.error('reports.record-panel', error)`); the header (Open as full screen, ✕) stays. The component is keyed by `dr`, so another record mounts fresh. `lazyChunk` keeps its first promise for the session, so `registered-panels.ts` wraps each entry in `reloadableChunk`, and the boundary calls its `reload` after it catches (after the error text has replaced the panel, so no render starts a load it then drops): the next record opened in the panel, or the same record opened again, loads the chunk again.
- **R15 — the generator's checks.** `component` passes `assertSafeExportSubpath('reportPanels[].component', …)` (no `..`, no leading `/`, safe characters), and resolves as `<package name>/<component>` through the package's `exports` map, as `settings[].component` does. `path` is one or more segments of `[A-Za-z0-9_-]+` joined by `/`; one package's paths are distinct.
- **R16 — Select over text keeps every other rule.** A select column still has its options checked against its values; a text column is not checked (it has none). A stored value no option names shows as itself (the engine's `optionLabelSQL` and the client's `cellDisplay` already fall back to the value).
- **R17 — the zone in vitest.** A test that needs a zone passes it (`dateTimeText(v, 'America/Chicago')`, `zoneLine(cols, 'America/Chicago')`); a test through `cellDisplay`, `rowLabelText` or `optionText` compares with `dateTimeText(value)`, which holds in any test zone. The literal "4:07 PM" holds where the test runtime's locale is 12-hour (en-US, as on CI and the dev machines); `formatDateTime(…, true/false)` pins both cycles regardless.
- **R18 — the e2e's expected time.** The spec reads each sale's `created` with a read-only REST GET (allowed) and formats it in Node with `toLocaleString('en-US', …)`, which gives the same "Nov 14, 2026, 4:07 PM" form; it never imports core's formatter. The stub's sales have only server-set times, so the edges of local days are pinned in Go (Task 4), not in the e2e.
- **R19 — the stub panel path.** The stub's panel lives at `salesstub/panel/<id>`, not `salesstub/sale/<id>`: the drill specs press rows whose `open` is `salesstub/sale/…` at 1440 and expect a push, which a registered `sale` panel would change.

## Open questions

- **Q1 — the row mark after a reload or a pasted link.** The spec keeps the panel in the URL as `dr=<app path>` only; a path does not name a row (many audit rows open one record). Recommended: keep the row id in the UI store (R11); after a reload the panel shows and no row is marked until the next press. Cost: a reader who reloads loses the mark. Alternative: a second key `drr=<row id>` (also never in a copied link); cost: one more URL key and a spec change.
- **Q2 — reading the device zone once per app start (R3).** Recommended: yes, one zone per app session, so the rows, the cells and the header never disagree. Cost: a device that changes zone while the app runs keeps the old zone until restart. Alternative: re-read on every app foreground (AppState) and put the zone in the run key; cost: every open report reruns when the zone changes, and a little more code.
- **Q3 — a `DateTime` compared with a day typed in a filter (R1 limit).** A builder condition such as `gte(posted_at, {value: "2026-11-14"})` compares in UTC, while a period chip over the same field compares in the reader's zone; a reader in Chicago who types "on or after Nov 14" also gets the rows of Nov 13 from 6 PM. Recommended: accept for now, state the limit in `docs/packages.md` and the help (Task 9 does), and point readers to the period chip. Cost if wrong: a user-built report filtered by a typed day shows rows up to one zone offset off at each end of the day; Books reports built over `posted_at` with a typed day show it. Alternative: zone a literal day too when the other side is a `DateTime` (`expr.zoned` on a day-typed literal, in `formula.go`); cost: one more zoned operand kind and its tests, and a builder filter's rows change for every non-UTC reader.
